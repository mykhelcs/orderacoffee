04 · System Scope

Scope & Project Boundaries

05 / 16

Included in Scope

  • Single-Shop Operations: Tailored exclusively for CafeGO coffeehouse workflows.
  • Payments: Cash-on-Delivery, Pay-at-Counter, and PayMongo (GCash, Maya, Card + Sandbox Demo).
  • Delivery Maps: Saved addresses & coordinates via Leaflet (flutter_map).
  • Platforms: Android API 28+ mobile app + Flutter Web build.

Intentional Boundaries

  • No Multi-Merchant Routing: Focused on one shop branch.
  • No Hardware POS Terminal: Cashless runs digitally via PayMongo.
  • No 3rd-Party Fleet APIs: Handled by in-house CafeGO couriers.
  • Online Sync Required: Prevents ordering out-of-stock ingredients offline.

07 · Order Lifecycle

Deterministic Order State Machine

08 / 16
RECEIVEDNew order placed · Customer cancel allowed here
→
PREPARINGBarista active · Countdown timer running
→
READYReady at counter · Driver unlocked to complete
→
COMPLETEDHanded off / Paid · Loyalty stamp granted

Safe Cancellation Rule

Customers may cancel only while status is received. Once barista preparation starts, cancellations are blocked.

No Invalid Jumps

Both app logic and Firestore Security Rules enforce monotonic state progression and reject illegal transitions.

Technology Stack & Clean Layered Structure

11 / 16

Core Stack

  • App: Dart 3.5+ & Flutter (Material Design 3)
  • State & Routing: flutter_riverpod + go_router
  • Cloud: Firebase Auth, Firestore, Storage, FCM
  • Utilities: flutter_map, qr_flutter, mailer, crypto

Strict Separation of Layers

  • lib/backend/models — Typed immutable data classes
  • lib/backend/repositories — All Firebase reads/writes
  • lib/backend/services — PayMongo, SMTP, SHA-256 hashing
  • lib/frontend — UI features & Riverpod providers only

12 · Penetration Test Audit

Security Hardening Applied for Final Release

13 / 16

Auth & Transport Security

  • Hashed OTPs: Replaced plaintext OTP storage with salted 64-char SHA-256 codeHash.
  • No Auto-Admin Startup: Removed silent admin auto-login from main.dart and hardcoded fallback password.
  • TLS Enforced: Custom SMTP now sets allowInsecure: false.
  • Release Guards: Lookalike admin domains rejected; Google dev popup hidden in release builds.

Orders & Payment Protection

  • PayMongo Reference Match: Pre-allocates Firestore order ID before creating checkout sessions.
  • Rule Tamper Guards: New orders cannot force paid; cancel edits only status & updatedAt.
  • Anti-Hijack Delivery: Drivers cannot steal claimed orders or mark non-cash orders paid.
  • Live Demo Preserved: Sandbox Authorize Payment Now / PAY controls remain active for demo.
