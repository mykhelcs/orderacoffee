01 · Problem & Objectives

Solving Peak-Hour Coffeehouse Bottlenecks

03 / 20

Operational Pain Points Identified

  • Morning & Afternoon Queue Congestion: Counter-only ordering creates long physical lines and slow throughput during rush windows.
  • Customization Errors & Lost Chits: Verbal instructions, illegible handwriting, and scattered Messenger/SMS orders lead to wrong milk types, missed syrups, or dropped tickets.
  • No Streamlined Reordering: Regular patrons must re-specify their exact drink modifiers every visit.
  • Zero Management Visibility: Owners lack live insight into daily gross revenue, payment mix, sold-out ingredients, and preparation latency.

Six Engineered System Objectives

  • 1. Accurate Drink Customization: Dynamic bottom sheet for size, milk substitute, sugar level, ice preference, and add-ons with instant total pricing.
  • 2. Queue Reduction: Order-ahead Pickup, Dine-in, and Delivery flows reduce counter dwell time.
  • 3. Unified Barista KDS: Single oldest-first (FIFO) ticket queue prevents dropped orders.
  • 4. One-Tap Reordering & Favorites: Repeat prior orders and save signature drinks in one tap.
  • 5. Real-Time Inventory Control: Sold-out toggles propagate to customer screens immediately.
  • 6. Strict RBAC Isolation: Firebase Auth + Firestore Security Rules isolate data by role.

02 · Target Users & RBAC

Four Scoped Operational Personas

04 / 20
Role: customer

Customer Application

  • Browse & search live beverage and pastry catalog.
  • Customize drinks with dynamic pricing & cart special notes.
  • Place Pickup, Dine-in, or Delivery orders (PayMongo or Cash).
  • Track live 4-step preparation progress, view QR receipt, earn 8-stamp loyalty rewards, reorder history, save favorites, and submit 1–5 star ratings.
Role: staff

Barista / Staff KDS Workspace

  • Stream incoming active orders sorted oldest-first (FIFO).
  • Track live elapsed prep timers and inspect full modifier breakdowns.
  • Process Cash / Pay-at-Counter tenders via Cashier change calculator drawer.
  • Advance states (received → preparing → ready → completed) and toggle sold-out stock.
Role: admin

Store Administrator Console

  • Full catalog CRUD: create, edit, price, categorize, hide, and delete menu entries.
  • Upload high-resolution item photography to Firebase Storage.
  • Inspect daily revenue metrics, order volume, and payment breakdowns.
  • Manage user roles (customer / staff / driver / admin) with owner-only rules.
Role: driver

Driver / Courier Dispatch

  • Claim unassigned delivery orders with atomic anti-hijack protection.
  • Inspect verified customer address, notes, phone contact, and Leaflet GPS map coordinates.
  • Update simulated/live rider coordinates along the route.
  • Mark COD collected only after kitchen reaches ready; track courier earnings.

02 · Scope, Boundaries & Impact

System Boundaries & Operational Benefits

05 / 20

Explicit Project Boundaries

  • Single-Branch Scope: Engineered specifically for CafeGO single-shop operations; multi-merchant or franchise routing is outside scope.
  • Payments Supported: Supports Cash-on-Delivery, Pay-at-Counter, and PayMongo gateway (GCash, Maya, Card) plus sandbox demo controls; no physical POS card-swipe terminal hardware.
  • Delivery Logistics: Uses structured addresses and map coordinates with internal courier dispatch; third-party fleet APIs (GrabExpress / Lalamove) are excluded.
  • Online-First Sync: Active internet connectivity is intentionally required to prevent stale inventory and overselling out-of-stock ingredients.
  • Target Platforms: Android API 28+ primary target alongside responsive Flutter Web deployment for grading & desktop review.

Expected Operational Benefits

Shorter Peak Queue Times

Order-ahead scheduling and live readiness alerts shift ordering away from crowded counter bottlenecks.

Zero Customization Ambiguity

Structured modifier keys guarantee baristas always see exact size, milk, sugar, ice, and add-on parameters.

Centralized Ticket Integrity

Cloud Firestore eliminates duplicated paper chits, missed Messenger threads, and forgotten orders.

Higher Patron Retention

8-stamp loyalty rewards, Favorites, and one-tap History reordering drive repeat visits.

03 · System Flows & State Machine

End-to-End Operational Lifecycles

10 / 20

Deterministic Order State Machine (OrderStatus)

RECEIVEDCheckout placed • Customer cancel allowed only here
→
PREPARINGBarista claims • Prep countdown starts
→
READYAt counter or ready for Courier handoff
→
COMPLETEDPicked up / Delivered • Stamps awarded

Customer Cancellation Branch: RECEIVED → CANCELLED is allowed exclusively before barista prep starts; terminal states (COMPLETED / CANCELLED) reject further transitions with OrderStateFailure.

Customer Flow

Sign Up / Verify OTP → Browse & Search → Customize Drink Sheet → Cart Review → Checkout (Pickup / Dine-in / Delivery) → Live 4-Step Tracker → QR Receipt → Rate & One-Tap Reorder.

Staff KDS Flow

Role-guarded Login → FIFO Queue Stream → Inspect Modifiers & Notes → Tap Start Preparing → Tender Cash via Cashier Drawer → Mark Ready → Mark Completed.

Driver Flow

Driver Login → Delivery Queue → Claim Unassigned Delivery → Inspect Notes & Map Coords → Wait for Kitchen Ready → Deliver & Collect COD → Mark Completed.

04 · Routing & Access Control

Declarative GoRouter & Role-Based Redirect Guards

14 / 20

Reactive Route Guard Pipeline

Riverpod authProviderAuth token + users/{uid}.role
→
RouterNotifierTriggers GoRouter refresh
→
Declarative GuardEvaluates allowed route prefix
→
Target WorkspaceScoped shell rendered

Strict Role Redirection Rules

  • Unauthenticated Users: Blocked from private routes and redirected to /login.
  • Pending Verification: Unverified email/password signups are directed to /verify-email.
  • Customers: Strictly prevented from accessing /staff, /admin, or /driver namespaces.
  • Staff / Admin / Driver: Automatically landed in their dedicated workspaces (/staff, /admin, /driver).

Multi-Channel Deep Link Support

  • Tracking Routes: /tracking/:id and /receipt/:id resolve directly from checkout or notification taps.
  • PayMongo Return Path: Preserves order ID alignment after sandbox/live external browser redirects.
  • Zero Context Coupling: Auth redirects run purely from reactive router state with no imperative navigation hacks inside repositories.

Final Touch · Penetration Testing Audit

Security Vulnerabilities Identified & Remediated

18 / 20

Authentication & Credential Hardening

  • Hashed OTP Verification: Replaced plaintext code writes in email_verifications with salted 64-character SHA-256 codeHash; enforced in firestore.rules.
  • Removed Auto-Admin Backdoor: Deleted silent startup ensureAdminAccountExists() from main.dart and removed hardcoded admin password literal from AuthRepository (reads ADMIN_PASSWORD env only).
  • Strict Domain & Release Guards: AdminConfig.isAdminEmail rejects lookalike domains; Google Sign-In dev popup guarded with !kReleaseMode.
  • SMTP TLS Enforcement: Changed custom SMTP settings from allowInsecure: true to allowInsecure: false.

Firestore Rules & Payment Integrity

  • PayMongo Reference Alignment: Pre-allocated Firestore doc ID (allocateOrderId()) prior to creating PayMongo checkout sessions so gateway referenceNumber matches the Firestore order ID.
  • Order Rule Tamper Guards: /orders create forces paymentStatus in ['unpaid','pending'], non-empty items, and subtotal >= 0; customer cancel updates allow only ['status','updatedAt'].
  • Driver Anti-Hijack Rules: Delivery updates forbid overwriting an existing driverId and allow driver paymentStatus updates only on cash orders.
  • Demo Readiness Preserved: Retained PayMongo sandbox presentation demo controls (Authorize Payment Now / PAY) for live defense walkthroughs.
